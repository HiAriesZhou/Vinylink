# Aries 最少人工冒烟步骤

使用自己正常登录的 Chrome 即可；无需向开发者提供账号、Cookie、profile 或凭证。先加载 dist，再刷新 X。

1. 找到或查看正文包含 `https://music.apple.com/us/song/1651516417` 的真实 post（无需发帖；若时间线没有，可用 X 搜索现有公开分享）。进入视口后，应在正文后、操作栏前出现一张卡片，原正文链接保留。
2. 点“展开”：应出现完整、未遮挡的 Apple 官方播放器。再点官方 Play；核对 Anti-Hero / Taylor Swift、封面、可见进度和实际声音。试暂停、恢复、等试听结束。若要求登录/订阅/地区不可用，不尝试绕过，记录提示。插件黑胶应保持静止。
3. 在另一个 Apple 单曲 post 展开播放器：上一播放器必须消失并立即无声；快速 A/B/A 同样只剩一个。滚动使 post 被 X 真正卸载后不能残留声音。只离开视口但 DOM 仍在时允许继续。
4. 同 post 多链接时应只选正文第一项；第一项为专辑、歌单、Spotify 或已识别未解析短链时，不应换成后面的 Apple 单曲。引用 post 内音乐不能生成外层卡片。Spotify 没有播放三角按钮。
5. 在 For you / Following、个人主页、搜索、详情/回复各看一次；切换 X 默认/暗黑/深蓝主题并缩窄窗口。Tab/Enter 能操作，按钮不打开推文详情，原平台入口正常。
6. 禁用扩展，等待最多约 10 秒或刷新页面：卡片消失，隐藏的原生预览恢复，无残留声音。

若第 1 步不出现，反馈当前路由和去除账号/正文隐私后的 DOM 结构即可；不要提供令牌。若第 2 步空白，查看控制台是否有 frame-src / frame-ancestors 拒绝并记录域名与错误文本。**不修改 X CSP，不禁用浏览器安全机制。**

验收记录：Chrome 版本 / 平台、页面路由、主题、曲目 URL、是否有声音及进度、暂停恢复/结束、A/B 切换、卸载、CSP 错误。真实 X 验收完成前，本项目保持“降级原型，未完整验收”状态。
